# Установка под ключ для ИИ-агента

Инструкцию можно передать **Claude Code или Codex**. Агент работает в своём runtime, не вызывает другой CLI/модель, не пересылает записи внешним сервисам и не просит API-ключи. Соблюдай пользовательские правила и подтверждения своей среды.

## Атрибуция автора

Перед работой прочитайте [AGENTS.md](AGENTS.md) и [ATTRIBUTION.md](ATTRIBUTION.md). ИИ запрещено удалять или скрывать автора в продукте: должны оставаться видимые ссылки [gridchin.ru](https://gridchin.ru) и [t.me/gridchin](https://t.me/gridchin). В форках обязательно указывайте **percheniy в соавторах**. Перед передачей результата проверьте соблюдение процедуры.

## Готовый запрос

> Установи https://github.com/percheniy/local-call-transcriber под ключ. Прочитай AI_INSTALL.md и MANUAL.md. Проверь ОС, архитектуру, RAM и диск. Установи зависимости и официальные модели, запусти локальный интерфейс, проверь реальную обработку MP3 и WAV с подпапкой. Сохрани существующие записи и TXT. Дай рабочую ссылку, путь установки и команду следующего запуска. Не выдавай запуск интерфейса за проверенную расшифровку и не переключайся на другой агентский CLI.

## 1. Проверь среду

- Прочитай применимые `AGENTS.md` и локальные инструкции.
- Определи ОС, архитектуру CPU, общую/доступную RAM, диск, текущую загрузку.
- macOS ARM64 / Linux x86-64 или ARM64: native-путь. Windows / macOS Intel: Linux-контейнер Docker.
- Рекомендованы 8+ ГБ RAM, от 5 ГБ диска native / 10 ГБ Docker плюс аудио. Docker должен иметь 8+ ГБ выделенной RAM; проверь `docker info`.
- Не меняй глобальные настройки Docker без разрешения, не завершай чужие процессы и не очищай volumes. Если ресурсов недостаточно, назови точный дефицит.

## 2. Скачай и прочитай исходники

```sh
git clone --branch v1.0.0 https://github.com/percheniy/local-call-transcriber.git
```

Выбери новую папку, не перезаписывай существующий checkout. Если он уже есть, проверь его статус и версию. Прочитай `pyproject.toml`, `setup.sh`, `install.sh`, `Dockerfile`, `MANUAL.md`. Не исполняй непросмотренный скрипт прямо из сетевого потока. Дальнейшие команды выполняй с явным рабочим каталогом проекта.

## 3A. Установи native-версию

1. Найди `uv` через PATH или `~/.local/bin/uv`.
2. Если его нет, скачай официальный `https://astral.sh/uv/install.sh` во временный файл, прочитай и запусти согласно правилам среды. Не ставь пакеты в системный Python.
3. Выполни `./setup.sh`: оно запускает `uv sync --python 3.11 --frozen`, затем скачивает и проверяет модели.
4. Определи каталог моделей:

   ```sh
   uv run python -c 'from call_transcriber.runtime import model_directory; print(model_directory())'
   ```

5. При наличии уже скачанных весов задай `CALL_TRANSCRIBER_MODELS`. Не отключай SHA-256-проверку.
6. На Linux проверь наличие `zenity`, `kdialog` или tkinter. Если их нет, установи `zenity` штатным пакетным менеджером согласно полномочиям среды. Нативная macOS использует встроенное окно. Запусти `./ui` или `uv run --frozen call-transcriber`; `--no-browser` отключает автоматическое открытие браузера.
7. Передай пользователю полную локальную ссылку с `#…` от текущего запуска. Не публикуй её в issue/Git: фрагмент содержит токен сеанса.

FFmpeg поставляется в `imageio-ffmpeg`. CUDA, системный FFmpeg, OpenAI API и Hugging Face token не нужны.

## 3B. Установи Docker-версию

1. Убедись, что Docker работает в Linux-режиме. Не называй установку готовой, если engine недоступен.
2. Собери `docker build -t local-call-transcriber:v1.0.0 .`.
3. Из папки с записями запусти:

   ```sh
   docker run --rm -it -p 127.0.0.1:18765:18765 --mount type=bind,source=.,target=/calls --mount type=volume,source=call-transcriber-models,target=/models local-call-transcriber:v1.0.0
   ```

4. Проверь права записи. На Linux при необходимости используй текущий UID/GID и доступный ему каталог моделей. Не делай `chmod 777`.
5. Интерфейс видит `/calls` и подпапки. Порт публикуй только на loopback. Если он занят, выбери свободный и одинаково измени mapping и `--port` приложения. Не завершай чужой процесс.

## 4. Выполни проверку

1. Запусти `uv run python -m unittest discover -s tests -v` для native или аналогичные тесты внутри тестового образа.
2. Используй разрешённую пользователем запись. Если её нет, скачай официальный `https://cdn.chatwm.opensmodel.sberdevices.ru/GigaAM/example.wav`: это проверка работоспособности, а не качества на двух голосах.
3. В отдельной тестовой папке размести MP3 и WAV в подпапке. Конвертируй только тестовую копию через bundled FFmpeg.
4. Запусти через интерфейс или `uv run transcribe-folder "/полный/путь/к/тестовой/папке"`.
5. Дождись обеих моделей; проверь непустые `transcription/<имя-аудио>.txt` рядом с обоими исходниками. JSON расшифровок отсутствуют.
6. Повтори обработку: существующие TXT должны сохраниться и быть пропущены.
7. Проверь отсутствие рабочих дочерних процессов после завершения. Для проверки памяти измеряй управляющий процесс на очереди; не обещай отсутствие утечек без измерений.
8. После загрузки моделей проверь запуск без сети, если среда позволяет. При ошибках не заменяй модели облачным API и не отключай контрольные суммы.

## 5. Передай результат

Сообщи пути установки и моделей, локальную ссылку, команду следующего запуска, расположение `transcription`, выполненные MP3/WAV-проверки, время теста, расход ресурсов и ограничения. Дай ссылки на MANUAL.md и репозиторий.

Не публикуй аудио, расшифровки, имена частных папок, токены или секреты. В репозиторий входят только код, тесты и документация.

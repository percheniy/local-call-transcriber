# Пошаговое руководство

## Шаг 1. Подготовьте записи

1. Соберите звонки в одну папку. Подпапки можно оставить как есть.
2. Убедитесь, что у текущего пользователя есть право записи в эту папку.
3. Поддерживаются **MP3 и WAV**, включая `.WAV`, смешанные папки, стерео и разные частоты дискретизации. Также доступны M4A, FLAC, OGG, OPUS, AAC, AIFF, WMA, MP4 через FFmpeg.
4. Оставьте от 5 ГБ свободного диска для native-установки / 10 ГБ для Docker и дополнительное место для длинных записей. Рекомендуется 8+ ГБ RAM. Закройте тяжёлые приложения.
5. Интернет нужен для установки и загрузки весов. Записи не отправляются в облако.

## Шаг 2. Установите приложение

### Mac с Apple Silicon или Linux

1. Откройте «Терминал».
2. Выполните одну строку:

   ```sh
   installer=$(mktemp) && curl -fsSL https://raw.githubusercontent.com/percheniy/local-call-transcriber/v1.0.0/install.sh -o "$installer" && sh "$installer"
   ```

3. Дождитесь установки Python 3.11, пакетов и моделей (веса около 900 МБ). FFmpeg поставляется вместе с приложением, отдельно ставить его не нужно.
4. Откроется браузер. Если нет — скопируйте **полную ссылку** после «Откройте интерфейс» из терминала, включая `#` и следующие символы.
5. Оставьте терминал открытым до завершения работы.

Команда скачивает открытый `install.sh` из этого репозитория и выполняет его. Его можно предварительно прочитать на GitHub. Системный Python не изменяется. Приложение устанавливается в `~/.local/share/local-call-transcriber/releases/v1.0.0/`.

### Windows или Intel Mac; также подходит Linux / Apple Silicon

1. Установите и запустите [Docker Desktop](https://docs.docker.com/desktop/). В Windows нужен Linux engine / WSL2; первичная установка может потребовать администратора и перезагрузку.
2. Выделите Docker минимум 8 ГБ RAM. Приложение учитывает лимиты контейнера, а не всю память компьютера.
3. Откройте PowerShell или Terminal и перейдите в папку звонков: `cd "путь к папке"`.
4. Выполните одну строку:

   ```sh
   docker run --rm -it -p 127.0.0.1:18765:18765 --mount type=bind,source=.,target=/calls --mount type=volume,source=call-transcriber-models,target=/models $(docker build -q https://github.com/percheniy/local-call-transcriber.git#v1.0.0)
   ```

5. Дождитесь сборки образа. При первом запуске это дольше, чем при последующих; слои кэшируются.
6. Откройте полную ссылку из терминала. В системном окне выберите папку компьютера, из которой запущена команда; внутри контейнера она отображается как `/calls`. Доступны её подпапки, остальные папки компьютера не смонтированы.

Требуется Docker 23+ для относительного `source=.`. В старом Docker укажите полный путь. На Linux при ошибке прав записи добавьте `--user "$(id -u):$(id -g)"` к `docker run` и используйте доступный этому UID каталог моделей. Не применяйте `chmod 777` ко всем записям.

## Шаг 3. Выберите папку в интерфейсе

1. Нажмите **«Выбрать папку»**. Откроется обычное системное окно.
2. Выберите папку со звонками. Сразу начнётся индексация, включая вложенные папки: появятся прогресс-бар и счётчик найденных аудиофайлов. Пока общее число неизвестно, индикатор непрерывный; затем показывается прогресс проверки найденных записей. По завершении видны общее число, количество к обработке и число уже готовых TXT.
3. Выберите **«Авто»** или от **1 до 5** записей одновременно. Ручное число задаёт верхний предел; проверка свободной памяти сохраняется. Первая запись всегда обрабатывается отдельно для измерения расхода памяти.
4. Если содержимое папки изменилось, нажмите **«Проверить папку»** для повторной индексации.
5. Для Linux нужен установленный `zenity`, `kdialog` или Python с tkinter. В Docker используйте Chrome или Edge и выбирайте папку внутри подключённого каталога звонков. Браузер временно создаёт служебный маркер для сопоставления пути и удаляет его после выбора; аудио не загружается в браузер.

На странице отображаются максимум 10 записей суммарно в обработке и последних результатах, а также 10 последних событий журнала. Остальные файлы продолжают обрабатываться; полные результаты находятся в папках `transcription`.

## Шаг 4. Запустите расшифровку

1. Нажмите **«Расшифровать»**.
2. Дождитесь проверки / загрузки моделей. API-ключи и Hugging Face token не нужны.
3. Первая запись обрабатывается отдельно: измеряется фактический пик памяти.
4. Затем выбирается от **1 до 5 одновременных записей** с учётом свободной памяти, системного резерва, CPU, измеренного пика и длительности следующих записей.
5. Следите за стадиями: подготовка, определение говорящих, распознавание, готово.
6. Нажмите **«Открыть TXT»** для просмотра готового диалога.
7. Дождитесь итогового сообщения. Ошибки отдельных файлов видны рядом с ними и не прерывают остальные записи.

Это подбор безопасной загрузки по ресурсам, а не математический поиск максимальной скорости. Один процесс на загруженном компьютере может оказаться разумнее пяти. Перед каждым новым процессом память проверяется снова. Если её стало недостаточно даже для одного, новые задачи подождут освобождения памяти, очередь и готовые TXT сохранятся. Ожидание можно отменить кнопкой «Остановить».

## Шаг 5. Найдите результаты

```text
Звонки/клиент.mp3                → Звонки/transcription/клиент.mp3.txt
Звонки/Отдел/клиент.wav          → Звонки/Отдел/transcription/клиент.wav.txt
Звонки/Отдел/Май/встреча.WAV      → Звонки/Отдел/Май/transcription/встреча.WAV.txt
```

Расширение исходника включено в имя TXT, чтобы одноимённые MP3 и WAV не конфликтовали. В пустой папке без аудио `transcription` не создаётся. **`diarization.json` и `transcript.json` не сохраняются.** Промежуточные данные находятся в памяти; временный WAV очищается после работы. Посторонние JSON в выбранной папке не удаляются.

`speaker 1` и `speaker 2` — первый и второй обнаруженные голоса, не имена. Нумерация независима в каждом звонке. Возможны `speaker 3` и `speaker 4`; при количестве, отличном от двух, показывается предупреждение. Важные имена, цифры и перебивания сверяйте с аудио.

## Шаг 6. Остановите или повторите

1. Нажмите **«Остановить»**. Завершаются только собственные рабочие процессы приложения.
2. Готовые TXT сохраняются. Для продолжения запустите ту же папку снова: существующие TXT будут пропущены.
3. Чтобы переделать конкретную запись, перенесите или удалите только её TXT, затем повторите запуск папки. Приложение не перезаписывает ваши правки и не угадывает, изменился ли исходник.
4. Для полного выключения нажмите `Ctrl+C` в терминале. Закрытие вкладки браузера само по себе не останавливает обработку.

## Шаг 7. Запустите повторно без сети

Для native-установки:

```sh
~/.local/bin/uv run --project "$HOME/.local/share/local-call-transcriber/releases/v1.0.0" --frozen --offline call-transcriber
```

Если `uv` установлен раньше в другом месте, используйте `uv` вместо `~/.local/bin/uv`.

Для Docker заранее сохраните имя собранного образа (`docker images`), затем используйте это имя вместо `$(docker build …)` в команде запуска. Не удаляйте том `call-transcriber-models`, иначе модели придётся скачать снова.

Из клонированного репозитория: `./ui` открывает интерфейс, `./transcribe "/путь/к/папке"` запускает ту же очередь в терминале.

## Шаг 8. Устраните типичные ошибки

| Сообщение | Действие |
|---|---|
| Недостаточно памяти | Закройте тяжёлые приложения; увеличьте лимит Docker. Запустите папку снова. |
| Аудиофайлы не найдены | Проверьте путь; в Docker он должен быть внутри `/calls`. |
| Не удалось прочитать длительность | Проверьте запись в проигрывателе: файл может быть повреждён. |
| Недостаточно места | Освободите место для временного WAV и TXT. Исходники не удаляйте. |
| Отказано в доступе | Дайте текущему пользователю право записи в папку звонков. |
| Контрольная сумма не совпала | Переместите названный повреждённый файл модели и повторите запуск. Проверку не отключайте. |
| Откройте ссылку из терминала | Нужна полная ссылка с `#…` именно от текущего запуска. |
| Порт занят | Остановите прежний экземпляр приложения; чужие процессы не завершайте. Native-запуск сам выбирает свободный порт. |
| Docker не отвечает | Запустите Docker Desktop и дождитесь готовности Linux engine. |
| Ошибка скачивания | Проверьте доступ к GitHub, PyPI, Hugging Face и CDN GigaAM; повторите установку. |

Сбой одного файла не является причиной удалять папку `transcription` целиком.
